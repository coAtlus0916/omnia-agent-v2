# ADR-0015：聊天正文立即删除并分离保留必要证据

状态：Accepted  
日期：2026-07-30  
决策者：用户

## Context

“删除聊天记录”只处理 Omnia Agent v5 本地主界面第三列中的当前会话，不处理 Omnia 平台数据。聊天正文、聊天专属附件、Run、Omnia effect Evidence 和共享 Artifact 的生命周期不同；若把它们一起删除，会丢失危险操作和未知结果的必要证据；若全部保留，又会使“删除聊天记录”名不副实。

公司当前没有额外的数据保留期限规定。产品需要给出用户可理解、可验证且不会伪装彻底删除的默认语义。

## Decision

1. 用户查看真实影响摘要并明确确认后，当前会话的 `ChatMessage` 正文立即物理删除，不设置用户回收站。
2. 仅被这些聊天消息引用、没有其他引用且不受活动状态约束的附件由 Artifact 清理器物理删除。
3. 以下事实与聊天正文分离保存，不随聊天删除：
   - 已发生 Omnia effect 的 Run/Command/Evidence；
   - 仍为 `uncertain`、正在对账或无法证明结果的命令；
   - 被其他 Run、会话、模板或业务结果引用的 Artifact；
   - 证明用户确认、目标摘要、结果和时间所需的最小 Evidence。
4. 保留 Evidence 不复制聊天正文，只保留不可变 ID、digest、计数、时间、决定、effect/结果状态及必要的脱敏摘要。
5. 存在活动 Run、活动/暂停录制、上传、待确认操作、未解决 `uncertain` 或引用图不可可靠读取时，删除失败关闭。
6. 删除结果必须分别报告正文已删除数、附件已删除数、保留对象数及保留原因；不得声称已删除整个会话的所有业务和审计事实。
7. 会话容器和当前 FeatureContext 默认保留，第三列可继续新的对话；被删消息不得从缓存、Event 投影或重启恢复中重新出现。

## Consequences

- 用户点击删除后不会在普通产品流程中恢复聊天正文。
- 业务写入和未知结果仍可追踪，不会因为清理聊天而失去对账依据。
- 附件清理可能在正文事务完成后进入 `cleanup_pending`，但 UI 必须如实区分正文删除与附件清理状态。
- 若未来需要管理员备份恢复，必须由统一备份策略另行设计；本 Feature 不承诺回收站或恢复。

## Alternatives

### 普通用户回收站

拒绝作为首版默认。它增加恢复期限、二次清理、容量和权限语义，而用户已经接受立即删除。

### 连同 Run、Evidence 和所有附件一起删除

拒绝。它会破坏 Omnia mutation、`uncertain` 和共享引用的可解释性。

### 只在前端隐藏消息

拒绝。界面状态不能冒充真实数据删除。

## Verification

- 数据库事务失败时原消息仍可见；
- 成功后重启应用，已删消息不再出现；
- 无引用聊天专属附件被物理清理；
- 共享附件、活动 Run 和 `uncertain` Evidence 不被删除；
- Evidence 中不存在聊天正文副本，只保留合同允许的最小字段；
- UI 返回真实删除/保留/清理失败计数；
- local/remote 设置不改变本地聊天删除语义，且不调用 Connector。
