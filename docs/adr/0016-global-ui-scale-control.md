# ADR-0016：所有一级界面提供统一全局缩放控制

状态：Accepted  
日期：2026-07-30  
决策者：用户

## Context

v4 只为聊天正文和输入框提供独立字号设置，其他 React 工作台、设置和独立窗口使用各自字号。用户认为当前部分界面字体过大，希望所有界面右上角都提供 `−/+` 调节区域。

若每个页面保存自己的字号，会产生状态漂移、跨窗口不一致和 Feature 私有实现；如果按钮只修改当前 DOM，则重启后丢失，也违反真实状态门禁。

## Decision

- 所有一级界面和独立工具窗口右上角使用统一的 `− 百分比 +` 控制。
- 调整的是全局 Agent UI 视觉缩放，不是 Windows 窗口大小。
- 弹窗、消息卡和内嵌面板继承当前值，不重复放置控制。
- Core `UserPreferenceService` 是缩放设置唯一 owner，成功持久化后广播所有窗口。
- 首次为 100%，下次启动沿用上次成功值。
- 100% 仍使用紧凑默认密度，缩放不能代替合理的基础字号设计。
- Artifact 内容、模板渲染、导出文件和 Omnia 页面不受 Agent UI 缩放影响。
- 精确范围、步长以及 Electron/CSS 技术机制在 Windows 原型后冻结。

## Consequences

- 主界面、设置和 Feature 工具的可读性偏好一致；
- 独立窗口需要在正式绘制前读取设置并订阅更新；
- 所有布局、portal、拖拽和确认界面都必须加入非 100% 测试；
- v4 聊天专用 localStorage 设置不能原样成为 v5 的事实源，迁移时需映射或忽略；
- 不能为单个 Feature 私自增加另一套全局字号设置。

## Verification

- 公共 UserViewPreference 合同和 stateVersion 测试；
- 多窗口同步、重启恢复、保存失败回滚测试；
- Windows 系统缩放 × 应用缩放矩阵；
- 键盘、焦点、滚动、弹层定位和危险确认测试；
- Artifact/导出尺寸不变测试。
