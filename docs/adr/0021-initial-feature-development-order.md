# ADR-0021：首批 Feature 开发顺序

状态：Accepted  
日期：2026-07-30  
决策来源：用户产品决策  
Supersedes：ADR-0018 中“新建与关联是第一条实现和验收切片”的顺序决定，以及 ADR-0012 的历史实施顺序建议；Feature 范围、导航位置和“新建与关联”canary 合同保留

## Context

首批 Feature 范围已经固定为录制、删除元素、删除聊天记录、新建与关联。此前文档把“新建与关联”安排为第一条真实纵向切片，目的是尽早验证四 Plane 和 Omnia mutation 链路。

用户现将开发顺序调整为：

1. 录制；
2. 删除元素；
3. 删除聊天记录；
4. 新建与关联。

这项调整改变的是 Feature 的开发和验收先后，不改变功能树位置、各 Feature 的安全边界，也不缩减“新建与关联”用于验证四 Plane 的目标。

## Decision

1. 首批 Feature 的开发、真实闭环验收和开放顺序固定为：
   1. 录制；
   2. 删除元素；
   3. 删除聊天记录；
   4. 新建与关联。
2. **录制**是第一条开发切片。它先验证真实 Connector/Session 绑定、Local/Remote 等价、长运行 Run/Step/Event、Artifact 回传、完整性、脱敏和恢复，但不能用历史文件或模拟采集代替真实录制。
3. **删除元素**是第二条开发切片。它在 Connector 基础链路已经通过后验证安全锁、实时预检、确认、关系解除、真实 mutation、写后读回和 `uncertain/reconcile`。
4. **删除聊天记录**是第三条开发切片。它验证后台本地数据事务、引用约束、保留/清理、刷新和重启恢复；数据生命周期 ADR 未 Accepted 前不得开放声称“已彻底删除”的入口。
5. **新建与关联**是第四条开发切片，并作为首批完成前的四 Plane 综合验收。它保留 ADR-0018 已确定的窄 canary：一个 Generic Application、一个 Generic Database、两个 GRA core 和唯一 DB → APP 关系的双边读回。
6. 第四项通过后，只能证明上述窄 canary 和首批公共架构链路成立，不自动开放完整 v4 Phase 1、其他对象类型、Risk/Control 后处理或更多关系。
7. 公共合同、Store、隔离、Transport、Gate、安全和测试基础可以作为前置平台工作建设；但四个用户可见 Feature 不得跳过上述顺序宣称完成或开放。若顺序再次调整，必须记录新的用户决定。
8. 所有阶段都必须连接真实后台、真实状态和真实目标系统；mock、sample 或 hardcoded 数据只能用于明确标识的内部测试，不能作为发布验收或用户可用入口。

## Consequences

- “第一条开发切片”从新建与关联改为录制。
- 新建与关联从“先行架构切片”改为第四阶段的综合链路验收；其产品范围、模板原则、两阶段 mutation、partial/uncertain 和 canary 成功条件不变。
- 高风险删除 mutation 提前到第二项，因此在该阶段开始前必须完成确认、幂等、读回、对账和安全锁合同，不能等待第四项补齐。
- 删除聊天记录虽排在第三项，但仍受数据生命周期决定阻塞；开发顺序不构成绕过 DoR 的授权。
- 功能树仍按业务信息架构组织，不按照开发顺序重新排列；导航顺序与开发顺序是两类决定。

## Alternatives

### 继续先做新建与关联

四 Plane 覆盖完整，但不符合用户指定的新顺序。

### 先做删除聊天记录

外部依赖较少，但不能先验证 Connector 的长运行、Artifact 和 Local/Remote 路径，也不符合用户指定顺序。

### 四项并行开放

会同时引入录制、两类删除和多步创建 mutation 的未验证边界，难以判断公共架构问题来自哪条链路，也违背逐项真实闭环和故障隔离要求。

## Verification

- 文档、路线图、DoR/DoD 和验收矩阵使用同一开发顺序；
- 录制完成真实 Local/Remote 会话、Artifact 和断线恢复验收后，才把第一项标为完成；
- 删除元素完成安全锁、确认、写后读回和 `uncertain/reconcile` 后，才把第二项标为完成；
- 删除聊天记录只有在删除/保留/恢复语义冻结并通过引用测试后，才把第三项标为完成；
- 新建与关联完成真实非生产 APP/DB/GRA/关系 canary，并能用单一 `traceId` 查询四 Plane 证据后，才完成首批综合验收；
- 任一后续 Feature 的 Worker、Operation Module、升级或失败不破坏已经验收的前序 Feature。
