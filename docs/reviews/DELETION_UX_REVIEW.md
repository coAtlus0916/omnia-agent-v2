# 删除元素 UX 复核：保留 React，恢复消息卡确认

状态：Accepted Product Direction / User Confirmed  
日期：2026-07-30  
范围：设计复核，不修改 v4/v5 产品代码。

## 1. 结论

可以使用现有 React、后台删除计划和消息通知架构恢复原先更简洁的交互，不需要回退 React，也不需要删除现有安全能力。

应当恢复的产品体验：

1. 删除工作台只负责实时浏览、搜索和选择元素；
2. 创建计划后，只在右上角 Agent 消息卡中确认删除；
3. 执行进度、终止入口和最终结果也只在同一消息卡中展示；
4. 删除进入终态后，工作台自动强制重新读取真实目录；
5. 字体、行高和间距改为紧凑的 Navicat 式密度。

不应恢复的是旧实现中任何基于前端内存、陈旧目录或弱确认的做法。后台的安全锁、计划冻结、写前预检、持久状态、写后验证和 `uncertain` 必须全部保留。

## 2. v4 现状与根因

当前 v4 已经有两个展示同一 DeletionPlan 的 UI owner：

| 位置 | 当前责任 |
|---|---|
| React 删除工作台底部 | 计划列表、确认/取消、执行进度、终止、结果和确认关闭 |
| 右上角 Agent 消息卡 | 计划确认/取消、执行进度、终止、结果和确认关闭 |

这不是后端功能重复，而是 presentation owner 重复。两个界面调用同一组真实 API、读取同一计划状态，因此给用户造成“选完后下面又弹出一个界面”的冗余感。

Git 历史中的旧版删除工作台已经具备：

- 创建计划后提示去右上角消息卡确认；
- 右上角消息卡展示 pending/executing/terminal；
- 删除计划进入终态后重新读取删除目录。

React 重构保留了右上角消息卡、跨窗口 `postMessage/localStorage` 广播和后台计划 API，又在 React 工作台内增加了完整 DeletionPlanPanel；同时工作台轮询终态后只刷新计划，没有恢复旧版的真实元素目录刷新。

## 3. 唯一展示责任

### 3.1 删除工作台

只负责：

- 读取当前安全锁与真实元素目录；
- 工作区/类型树；
- 搜索、勾选和批量选择；
- 显示不可选择原因；
- 创建一次持久 DeletionPlan；
- 显示一行非交互状态：“删除确认已发送，请在右上角消息栏处理”；
- 收到终态事件后自动刷新目录。

不再展示：

- 删除计划历史列表；
- 第二套确认/取消按钮；
- 第二套进度面板；
- 第二套结果详情；
- 第二个“知道了”入口。

### 3.2 右上角 Agent 消息卡

是删除计划交互的唯一 owner：

- `pending_confirmation`：展开详情、确认、取消、暂不处理；
- `executing`：真实进度、详细步骤、终止后续删除；
- `completed/failed/invalidated/terminated`：真实结果、失败原因、查看详情、知道了；
- 刷新/重启后从后台恢复，不依赖前端临时状态。

### 3.3 后台与 Connector

完全不因 UI 简化而削弱：

- DeletionPlan/Confirmation/Command 继续持久化；
- 确认仍绑定精确 plan digest 且只能消费一次；
- 执行前继续比较安全锁、Engagement、对象、关系和并发 token；
- mutation 继续经过签名 Connector Operation；
- 每项写后读取；
- 响应丢失进入 `uncertain`，不自动重放。

## 4. 推荐布局

删除工作台采用两栏而非当前三栏：

```text
┌──────────────────┬──────────────────────────────────────────┐
│ 工作区 / 元素类型 │ 搜索 + 实时元素列表                       │
│ 紧凑树            │ 复选框 / 类型 / 名称 / 简短状态           │
│                  │                                          │
├──────────────────┴──────────────────────────────────────────┤
│ 已选择 N 个    [刷新目录] [发送删除确认]                     │
└─────────────────────────────────────────────────────────────┘
                                         右上角 Agent 消息卡 ↗
```

当前右侧“待删除元素”篮子已确定在删除模式移除：

- 已选数量放在固定底栏；
- 当前列表中的勾选状态就是选择事实；
- 完整目标清单在确认消息卡中复核；
- 跨类型选择可以在底栏提供紧凑摘要或“查看已选 N 项”，但不常驻第三栏；
- 共享的 React `LockedElementBrowser` 可保留篮子能力供 Phase 2 等其他场景使用，删除模式通过配置选择两栏，不全局删除组件。

目录树和元素列表之间的边界使用公共 Splitter，可由用户拖动并恢复默认；完整规则见 [统一可调整分区系统](../product/RESIZABLE_LAYOUT_SYSTEM.md)。

这样保留 React 组件化和共享能力，同时不让一个通用组件强迫所有 Feature 使用相同的三栏界面。

## 5. 紧凑密度建议

以下是设计目标，最终数值仍需 Windows 缩放验证：

| 元素 | 建议 |
|---|---|
| 主文字 | 12px；必要时 13px，不使用 14–16px 大卡片正文 |
| 次要文字 | 10–11px |
| 树行 | 24–28px |
| 元素行 | 34–40px，根据是否有错误说明自适应 |
| 列表/树 padding | 6–8px |
| 圆角 | 4–8px，减少大卡片感 |
| 状态 | 短文本/小徽标，不为每项创建大块说明卡 |
| 标题 | 12–13px + 字重形成层级，避免依赖大字号 |

样式应限定在删除 Feature 或统一密度 token 上；不能为修复删除页而意外缩小 Phase 2、设置或聊天。

用户仍可通过所有一级界面右上角的统一全局缩放控制进一步调整显示，见 [全局界面缩放](../product/GLOBAL_UI_SCALE.md)。全局缩放不能替代本节的紧凑默认值。

## 6. 自动刷新语义

创建计划后，删除工作台订阅该 plan 的后台事件，但不渲染详细计划面板。

当计划进入以下终态之一时，强制调用真实目录刷新：

- `completed`；
- `failed`；
- `terminated`；
- `invalidated`；
- `cancelled`。

其中 `failed/terminated` 也可能已有部分真实 effect，因此同样必须刷新。刷新要求：

1. 使用 `refresh=true` 或等价的绕过陈旧缓存合同；
2. 清除已删除或已失效的选择；
3. 保留仍存在的搜索词和当前树节点；
4. 如果节点已不存在，选择第一个真实可用节点；
5. 读取失败时显示“删除结果已记录，但目录刷新失败”，不得保留旧列表并伪装最新；
6. 页面关闭后重新打开，也必须取得真实新目录。

消息卡的终态和目录刷新是两件事：目录刷新失败不能把已完成删除改成失败，也不能把旧元素继续标为可删除。

## 7. 未来实现影响

现有架构只需 presentation 层调整：

1. React 工作台不再渲染 DeletionPlanPanel 和计划历史；
2. 删除模式不渲染 SelectedElementBasket 常驻栏；
3. 工作台保留轻量 plan 订阅，仅用于禁用冲突操作和触发目录刷新；
4. 右上角消息卡继续调用现有确认、取消、终止和 acknowledge API；
5. 跨窗口广播携带 plan ID/stateVersion，接收端重读后台状态；
6. CSS 使用删除模式的紧凑 token；
7. 后台 API、数据库、Connector Operation 和安全策略不因 UX 修改而降级。

这不是“恢复旧代码”，而是在现有 React 架构中恢复旧的责任分工。

## 8. 验收标准

- [ ] 删除工作台中不存在第二套计划列表、确认、进度或结果面板。
- [ ] 创建计划后，右上角消息卡在真实后台状态到达后出现。
- [ ] 只有右上角消息卡可以确认/取消/终止/关闭删除计划。
- [ ] 刷新或重启后，消息卡仍能恢复真实计划状态。
- [ ] 计划任一终态都会触发强制真实目录刷新。
- [ ] 已删除元素不会继续出现在刷新后的可删除列表。
- [ ] 部分失败/终止后，列表反映 Omnia 当前真实状态。
- [ ] 工作台默认是紧凑两栏，字体和行高通过 Windows 缩放验证。
- [ ] Phase 2 等共享浏览器使用方不受删除模式简化影响。
- [ ] 所有安全锁、确认、写后验证和 uncertain 测试继续通过。

## 9. 用户确认

用户已确认：

- 删除模式移除右侧常驻“待删除元素”篮子；
- 底栏只显示已选数量；
- 完整清单在右上角确认卡展示；
- 确认、进度、终止和结果只由同一消息卡承载；
- 删除进入终态后自动刷新真实目录。
